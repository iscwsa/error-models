# CLAUDE.md

Guidance for Claude Code (and other coding agents) working in this repository. The README's
[Technical details](README.md#technical-details) section describes the layout, namespaces, versioning,
identifiers, hashes and tools; this file adds the working rules.

## Set up and test

- `pip install -r tools/requirements.txt` into a virtual environment, then run `pytest` from the repository root.
- Tests that need ISCWSA's spreadsheets skip unless `ISCWSA_WORKBOOKS` names a folder holding the workbooks listed in
  `tools/workbooks.json` (checked by SHA-256). `ISCWSA_IPM_GUIDE` names a local copy of the IPM guide `.docx` for
  the IPM doc test. Without both, about 50 tests skip; with both, none should.
- CI (`.github/workflows/validate.yml`) runs `pytest`, `python -m tools.validate --registry .`,
  `python -m tools.make_spe90408 --check` and `python -m tools.release check`. Run the same before pushing.
- On Windows, clone with `git clone -c core.autocrlf=false`: generated JSON and the IPM fixtures are compared byte for
  byte and must stay LF (`.gitattributes`).

## Rules

- **Published sources only.** Every value and formula comes from a published ISCWSA source: the workbooks in
  `tools/workbooks.json`, the ISCWSA error-model definition, the diagnostics in `conformance/`, and the cited SPE
  papers. Never take values from vendor software, its output, or any private implementation.
- **Generated files.** `library/` and `models/` are generated by `tools.extract_xlsx` and `tools.make_spe90408`. Don't
  edit them by hand: change the tool or its inputs (`tools/errata.json`, `tools/model_ids.csv`,
  `tools/term_*.json`), regenerate, and confirm with `--check`.
- **Where a source is wrong or unclear, record it; don't fix it silently.** A change to formula text is an erratum
  in `tools/errata.json` with status `proposed`; only the sub-committee accepts it. A choice about how a formula is
  evaluated is a convention row (`C<n>`) in `docs/deviations.md`. The docs tests check that each convention cited in
  the docs has its row there.
- **Identifiers are permanent.** `tools/model_ids.csv` fixes each model ID and UUID. Never rename or renumber one, even
  when a sheet is renamed.
- **Naming.** Call the OWSG Rev 5.1 sets A and B "Generic ISCWSA" (namespace `generic_iscwsa`). Use "OWSG" only for
  earlier OWSG releases.
- **Nothing proprietary.** Never commit vendor IPM files or the IPM guide; the IPM fixtures in `tests/fixtures/ipm/`
  are hand-written. `docs/ipm.md` cites the guide but must not quote it (a test checks for runs of 12 or more of its
  words).
- **Releases** go through `python -m tools.release` (`docs/releasing.md`). Don't edit `$schema` / `$id` URLs by hand.
- **Pull requests.** One purpose per PR. When a change affects how something is used, built or run, update the README
  and `docs/` in the same PR.
